# 7. Диспетчеризация техники

> **Статус: Готово (v1).** *Закрывает проблемы: «нет регламента работ», «отсутствие взаимодействия между отделами», «нет автоматизации по незакрытым заявкам».*

ЦКП диспетчера: заявка закрыта вовремя, техника подобрана с максимальной маржой, собственный парк загружен.

---

## 7.1. Общие правила

### Алгоритм приёма заявки
1. Заявка поступает (от менеджера/клиента) → фиксируется в CRM/1С со статусом `Новая`.
2. Уточняются параметры: вид техники, объект, даты/смены, условия, контактное лицо.
3. Проверка приоритета и маржинальности.
4. Назначение техники → статус `В работе`.
5. Контроль исполнения → закрытие → статус `Закрыто`.
6. Проблемные заявки → статус `Проблема` + эскалация руководителю.

### Алгоритм подбора техники
1. **Сначала — собственный парк** (управляемость, маржа, контроль). Проверить загрузку и доступность.
2. Если своей нет/занята — наёмная техника от проверенных подрядчиков.
3. Расчёт маржи: цена клиента − себестоимость (своя) / цена подрядчика (наёмная). Заявки с маржой **< 15% — через согласование руководителя**.

### Приоритеты
1. Приоритет загрузки **собственного парка** (KPI диспетчера).
2. Крупные/приоритетные клиенты (энергетика, девелоперы, генподряд).
3. Закрытие **всех** потребностей клиента, включая разовые/невыгодные заявки (ценность «всё в одном окне»).
4. Скорость подачи — цель **1 час**.

---

## 7.2. Собственный парк
Категории собственной техники (подробные карточки — в разделе [Автопарк](#assets/01-avtopark)):
- Самосвалы
- Манипуляторы
- Экскаваторы
- Погрузчики
- Краны (новое направление)
- Коммунальная техника (илососы, КДМ, МТЗ)

> Цель загрузки фиксируется в CRM в реальном времени (план/факт %).

## 7.3. Наёмная техника
- **Поиск подрядчиков:** по базе проверенных поставщиков (см. [Поставщики](#assets/03-postavshchiki)).
- **Проверка поставщиков:** документы, надёжность, наличие техники, история. Проверку рисков ведёт СБ.
- **Маржинальность:** контролируется по каждой наёмной единице; цель — не работать «в ноль».
- **Регламент оплаты подрядчикам:** единые сроки и ответственные. *(Закрывает проблему «нет своевременной оплаты подрядчикам».)*

## 7.4. Работа с заказом (полный цикл)
```
Заявка → Подбор/назначение техники → Подача на объект →
Выполнение работ → Закрывающие документы (24 ч) → Оплата → Закрытие
```

### Регламент закрытия заявок и документооборота
- Единый процесс: от заявки → подачи → акта → оплаты.
- **Жёсткий срок: 24 часа на закрывающие документы.**
- Авто-напоминания клиентам по оплатам и документам.
- Контроль «висящих» заявок — еженедельный разбор, недопущение потери клиента.

### NPS и контроль качества
- Авто-опрос клиента после каждой заявки (оценка 1–10).
- Еженедельный разбор проблемных заявок; отработка негатива менеджером.

> **Заполнить.** Точные SLA по времени подачи по типам техники, шаблон чек-листа качества «звонок → подача → работа → закрытие».
